# 对话块批量确认与上下文评分设计

## 目标

减少短 VAD 片段在对话页和大模型队列中的数量。用户可一次确认多条说话人归属；大模型只对完整的对话上下文请求一次，并返回块级建议与句级评分。

## 边界

- 录音文件继续以本地 PCM 和 Ten-VAD 分段保存，避免超大文件。
- 物理文件边界不能成为对话、确认或模型评分的边界。
- 仅在本地成员归属已确认后才发送该对话块的模型请求。
- 声纹、录音和离线识别持续保存在手机；仅已确认的转写文本会发送给用户配置的大模型。

## 对话块

新增持久化 `ConversationContextBlock`，引用一个或多个 `LocalUtterance`。一个块记录：块 ID、录音组 ID、首尾时间、成员句子 ID、状态、模型复核状态、块级 Markdown。

本地构建规则：

1. 仅合并同一录音组中按时间相邻的句子。
2. 句间间隔不超过 3 秒、累计不超过 45 秒且转写不超过 180 个汉字时可继续合并。
3. 出现明显长静音、超过时长/文本上限或录音结束时，关闭当前块。
4. 块末尾没有自然停顿或 `。！？…` 时标记为 `awaitingContinuation`；下一个物理音频段的续句会加入该块。
5. 用户停止录音时，未闭合的尾句作为最后一个块提交。

因此，WAV 为存储而分段，但模型上下文会跨 WAV 合并，避免根据文件边界断句。

## 批量说话人确认

对话页以对话块卡片显示合并上下文、时长、待确认数与评分状态；卡片展开后显示原始句子。

- 每句有复选框，支持全选、取消全选。
- 选中任意多句后显示固定操作栏；选择一个家庭成员即批量更新所选句子的本地声纹样本和标签。
- 块内所有有文本句子均已确认后，块转入 `queued`；否则保持 `awaitingConfirmation`。
- 更正已确认的成员只重新归类本地声纹及已有分数，不重复调用模型。

## 模型评分

队列从“每句一个任务”升级为“每个已确认对话块一个任务”，全局仍严格串行并保留现有退避策略。

请求按时间顺序发送 `成员：原话`，要求返回：

- 块级 Markdown 沟通说明；
- 每个原始句子 ID 对应的整数分数，范围 -100 至 100；
- 每个原始句子可选的 Markdown 简要依据。

模型结果写回块和各句。家庭趋势仍按句级分数及最终成员归属计算，负分红色、正分绿色。

## 状态与错误处理

- `awaitingContinuation`：等待完整句，不进入确认或模型队列。
- `awaitingConfirmation`：可批量确认，不进入模型队列。
- `queued`、`retryWaiting`、`completed`：沿用现有串行与指数退避语义，但归属于块。
- 模型输出缺失句级条目时，该条标为无评分而不伪造分数；块级说明仍显示。

## 验收与测试

1. 跨两个 WAV 的未结束句会合并为同一对话块。
2. 多选句子一次归属同一成员，且每个有效声纹样本均更新。
3. 存在任何未确认文本时，不产生模型请求。
4. 一个确认完成的对话块只产生一次串行请求，并按块级退避。
5. 模型结果映射回原始句子；更正成员后趋势重新归因而不重新请求模型。
6. UI 显示块级上下文、批量确认入口、块级 Markdown 与句级红绿分数。
